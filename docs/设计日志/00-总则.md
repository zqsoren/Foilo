## 按场景阅读

| 场景 | 阅读顺序与动作 |
|---|---|
| **新窗口接手** | 总则 → 模块索引 → 目标模块的当前状态、规则 → 从下一步继续；需要追溯时再查日志 |
| **跨设备接手** | 总则 → 跨设备同步 → 核对记录来源、同步版本与可访问文件 → 按新窗口路线接手 |
| 同一窗口继续 | 先确认总则、当前状态和规则是否有变化，再继续本轮范围；不必重读全部历史 |
| 开启新模块 | 总则 → 模块索引中的建档约定 → 复制三份模板，登记模块入口 |
| 涉及多个模块或共用能力 | 读全产品约定及各受影响模块的当前状态、规则，明确本轮边界 |
| 发布或回滚 | 读版本号、对应模块的当前状态及发布/回滚记录，按实际结果更新记录 |

## 记录怎样更新

1. **AI 维护本轮记录**：开始时在模块当前状态登记目标、端、工作窗口与范围。完成一段有实质变化的工作、结束本轮或准备换窗口/设备前，当次更新记录，不等用户提醒；中断且仍能保存时先记断点。
2. **当前状态持续更新**：替换过期进度，写清已完成、未完成、当前基准、下一步第一件事，以及尚未同步的文件。不按窗口另建一份交接。
3. **设计日志追加历史**：按日期和当日序号记录本轮结果、决定原因、相关入口、实际验证及遗留项。连续小调整可合记；旧事实需要更正时追加说明，只读且没有新结论时无需凑日志。
4. **其他文件按变化维护**：用户确认新规则后修改规则正文，日志留原因；模块启动或里程碑变化时更新模块索引；共用变化写项目日志；发布或回滚时更新版本表和模块记录。无需每轮改遍全部文件。
5. **据实标明状态**：网页、手机等端分别记设计、实现、验证和发布。建议与已确认决定分开，历史验证保留原日期；没有执行的检查写未验证。产品决定以用户最近确认的要求为准，运行状态以实际检查为准；发现冲突先说明。
6. **交接包含同步情况**：结束时简述成果、未完成或未验证项、下一步，以及仅本机、未提交或未推送的内容。已授权同步时，将本轮文件和记录一起同步；保存到本机不等于已同步到另一台。

## 共同约定

- 本轮任务先明确模块、端、目标和边界；保留其他窗口的改动，同一文件或设计画板交叉工作时先协调范围。
- 完整项目开始前核对分支、未提交文件和远端差异；不直接覆盖改动或强制处理冲突。仅有文档副本时注明来源及缺少的代码、素材或设计文件，不推定它们已同步。
- 文档使用相对路径，并尽量链接已有规则，避免多处各写一套。总则维护共同流程，全产品约定与模块规则分别维护各自内容；流程变化先更新本文件，再检查相关索引。
- 同步按已授权范围执行，不将密码、密钥、真实业务数据库或聊天恢复数据收进项目记录或源码仓库；具体方法查跨设备同步。
- 这些是供 AI 阅读执行的文字约定。首次使用其他 AI 工具时，明确让它先读本文件；文件本身不会后台执行或自动同步。
