# 在侧 Folio · 健身 · 设计与写作规则

> 阅读顺序：先读[协作总则](../00-总则.md)，再按任务阅读本文件。

板块名称为「健身」。品牌、共用登录入口、Figma EX 设计基准和布局调整流程沿用[全产品设计与协作约定](../在侧Folio-新窗口交接.md#全产品设计与协作约定)。

## 页面入口与用途

- 手机端用 `/gym` 记录自己的训练。
- 手机端「训练」首页兼作「我的计划」，展示自己建立的计划，并提供新建入口。点计划先预览该计划的动作及各动作组数，点击弹窗「开始训练」后进入训练，首页不放自由训练入口。
- 首页布局沿用用户手改的 01：计划卡双列错落，「新建计划」始终排在所有已有计划之后并随列表滚动。底部设训练、日历、动作库。[当前画板与预览](新窗口交接.md#当前设计与入口)
- 手机端另有训练进行中、训练日历（历史）和单次训练详情。动作库支持为计划添加多个动作。
- 手机动作库采用左侧竖向部位导航，右侧浅底双列动作卡。浏览点卡看详情，多选点卡切换选中。同一动作的简称和器械别名可用于搜索。
- 从「新建计划」进入动作库，先选所需动作，再加入训练计划。已有计划从首页经计划预览开练。
- 网页端用 `/gym/dashboard` 查看健身数据概览。

## 训练记录

- 用户进健身房时打开手机，开始记录本次训练，随训练进度逐组操作。
- 手机端提供动作库，训练中可以添加动作、为动作设置组数。每组都能手动填写实际重量和次数，做完一组即可单独点击完成。
- 用户可以新建自己的训练计划。
- 从底栏进入动作库仅浏览，沿用训练、日历、动作库三项悬浮导航，选中动作库。新建计划时多选动作，点完成后命名、保存并返回首页；训练中临时追加的动作只写入当次训练。动作图匹配器械与姿势，缺图保留相同尺寸的图位。
- 逐组记录支持重量与次数、左右分别记录、持续时间。可以新增加组、撤销完成、最小化继续、为本次训练中的当前动作保存心得。完成后查看时长、容量、完成组与未训练动作；日记按选中日期列出训练，统计共用训练数据。
- 容量口径为本阶段实现选择：仅累加完成组的外部负重。杠铃按含杆总重；双哑铃同步按单只重量 × 2 × 次数；左右独立按两侧重量 × 各自次数相加；自重只计额外负重，辅助配重与计时不折算 kg。日历按开始时的上海自然日归档，多次训练可合计。
- 账号与会话复用在侧，模块登录回跳区分手机与桌面。动作库和图像由服务端管理，各账号仅能访问自己的计划、训练与心得。
- 网页概览通过小组件展示训练数据。具体指标、排列顺序和同步细节待定。

## Figma 交付

手机界面使用白色或接近白色的浅底，整体极简。首稿用深色呈现标题、关键数字和主按钮，用浅灰区分输入框、列表分隔线和次级操作。选中或完成状态同时使用勾选标记。

在 `foilo-健身页面` 的「手机端」Page 内设计。图层按界面和功能区命名、编组，重复使用的动作行、训练组行等做成可复用组件。

计划的组织方式、训练页草案和下一步见[当前状态](新窗口交接.md)。每段实质工作追加到[设计日志](设计日志.md)；用户确认新规则时修改本页。窗口结束前按[总入口](../在侧Folio-新窗口交接.md)核对三份记录。

## 组别与历史记录

普通组和递减组按整组勾选。递减组每段记录独立的重量和次数，完成后累计各段容量、计一个完成组。组行依次显示组号、负重、次数、勾选及更多操作；计时动作显示秒数。更多菜单可转换为递减组或复制整组。复制保留全部段并置为未完成。历史详情底部可删除该次记录，确认后返回原日期；刚结束训练的总结仍可返回训练首页。

训练中点重量、次数或秒数直接在该框录入。重量允许小数，次数与秒数为整数。单侧动作分别编辑左、右值。切换字段与勾选可连续操作，只有组菜单和历史删除确认使用弹层。

训练中按当前动作查看上一次训练记录。动作名下默认显示一行摘要，点击展开可查看日期和每组的重量、次数，再次点击收起。历史数据只读，本次组表继续用于录入。

主导航为悬浮胶囊。训练、日历、动作库分别使用哑铃、日历页、四格图标，选中入口为 #242424 底、白色图标与文字。浏览动作库时三项导航选中动作库，半透明胶囊浮在列表内容上方；进行中的训练使用底部居中的浅色胶囊，最小化、加动作、写心得均为即时操作，使用深色图标与文字。计划双列的浅色实底采用 #F2F2F7。

手机主屏幕图标沿用 Figma EX 首页的 GYM 标志，保留白底、黑色图形、紫色中柱和底部 GYM 字样。桌面入口独立于 ToDo，启动后进入健身手机页。

计划预览的动作数和组数紧跟计划名，摘要锚定弹层顶部，所有动作数量采用同一标题间距。

首页「新建计划」按钮用阿里妈妈数黑体 Bold，字号 17 px，字距 0%。主稿与保存后、最小化等首页状态遵循同一样式。

## 动作库的部位与肌群

每个力量动作通常指定一个主练部位和一个主练肌群。对每个涉及的肌群标为「主练」「明显参与」或「顺带参与」。主练和明显参与均进入相应肌群小类及所属部位大类；顺带参与只在动作详情中说明。每个筛选结果按动作编号去重，跨分类共用星标与训练记录。三档表示训练侧重，无需估算百分比。

| 部位 | 肌群或训练侧重 |
|---|---|
| 背部 | 背阔肌、大圆肌、菱形肌、斜方肌上束／中束／下束、竖脊肌 |
| 肩部 | 三角肌前束／中束／后束、肩袖（冈上肌、冈下肌、小圆肌、肩胛下肌） |
| 臀腿 | 臀大肌、臀中肌、大腿前侧（股四头肌）、大腿后侧（腘绳肌）、大腿内侧（内收肌群）、小腿后侧（比目鱼肌、腓肠肌） |
| 手臂 | 二头、三头、肱肌、肱桡肌、前臂屈肌群、前臂伸肌群 |
| 腰腹／核心 | 腹直肌、腹斜肌、腹横肌、竖脊肌、前锯肌 |
| 胸部 | 上胸、胸中部、下胸 |

竖脊肌是背部与腰腹／核心共用的标签。有氧为独立分类，仅在「全部」和「有氧」列表展示。有氧卡片省略肌群三档及其编辑入口。

## 手机端原型页首与日历

整屏稿省去模拟系统时间、信号与电池，以 01 首页顶部 GYM 标志的可见边距（约 27 px）校准页首。日历年份在月份行右侧；训练日记与统计共用顶部居中双段切换栏；六周按 58 px 行距排列。日期数字、选中底、训练标签及相应点击区随所在周对齐。

## 动作主数据的同步来源

用户指定本机「已选动作肌群分类.html」为动作主数据来源。用户提出同步时，以四位动作编号关联名称、分类、器械、媒体和肌群档位，读取基础记录并叠加用户实际编辑页面所在浏览器保存的逐动作修改（folio-muscle-tags-v1:编号）。跨浏览器接手时须取得该浏览器的有效记录，单读 HTML 无法确认编辑后的标签。用户选图、修改标签或讨论设计时不触发生产同步。

原型优先复用已有画板，保留表达主要流程或关键差异所需的状态。纯样式调整直接同步主稿与现有状态。

训练总结按实际组顺序展示负重与次数、左右侧数据或时长。一个点对应一组，递减段缩进到同一个组号下。每组只区分已完成（深色实点）和未完成（浅灰实点），原计划与追加组采用相同点样式。卡片仅列实际完成的组次数据；省去图例、完成比例和组类型说明。至少完成一组的动作留在动作明细；完成零组的动作才列在底部「未训练」。

「写心得」打开时绑定本次训练的当前动作记录。切换动作后，各自读取、编辑自己的心得。训练总结及日记中的同次训练详情按动作展示，有内容时在对应卡片的组次点列下显示「本次动作心得」，无内容时收起该行。
