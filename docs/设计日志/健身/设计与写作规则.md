板块名称为「健身」。品牌、共用登录入口、Figma EX 设计基准和布局调整流程沿用[全产品设计与协作约定](../在侧Folio-新窗口交接.md#全产品设计与协作约定)。

## 页面入口与用途

- 手机端用 `/gym` 记录自己的训练。
- 手机端「训练」首页兼作「我的计划」，展示自己建立的计划，并提供新建入口。点计划先预览该计划的动作及各动作组数，点击弹窗「开始训练」后进入训练，首页不放自由训练入口。
- 首页布局沿用用户手改的 01：计划卡双列错落，「新建计划」始终排在所有已有计划之后并随列表滚动。底部设训练、日历、动作库。[当前画板与预览](新窗口交接.md#当前设计与入口)
- 手机端另有训练进行中、训练日历（历史）和单次训练详情。动作库支持为计划添加多个动作。
- 手机动作库采用左侧竖向部位导航，右侧动作列表，选中部位后左侧展开肌群索引。浏览点卡看详情，多选点卡切换选中。同一动作的简称和器械别名可用于搜索。
- 从「新建计划」进入动作库，先选所需动作，再加入训练计划。已有计划从首页经计划预览开练。
- 网页端用 `/gym/dashboard` 查看健身数据概览。

## 训练记录

- 用户进健身房时打开手机，开始记录本次训练，随训练进度逐组操作。
- 手机端提供动作库，训练中可以添加动作、为动作设置组数。每组都能手动填写实际重量和次数，做完一组即可单独点击完成。
- 用户可以新建自己的训练计划。
- 从底栏进入动作库仅浏览，沿用训练、日历、动作库三项悬浮导航，选中动作库。新建计划时多选动作，点完成后命名、保存并返回首页；训练中临时追加的动作只写入当次训练。动作图匹配器械与姿势，缺图保留相同尺寸的图位。
- 逐组记录支持重量与次数、左右分别记录、持续时间。可以新增加组、撤销完成、最小化继续、为本次训练中的当前动作保存心得。完成后查看时长、容量、完成组与未训练动作；日记按选中日期列出训练，统计共用训练数据。
- 容量口径为本阶段实现选择：仅累加完成组的外部负重。杠铃按含杆总重；双哑铃同步按单只重量 × 2 × 次数；左右独立按两侧重量 × 各自次数相加；自重只计额外负重，辅助配重与计时不折算 kg。日历按开始时的上海自然日归档，多次训练可合计。
- 账号与会话复用在侧，模块登录回跳区分手机与桌面。动作库和图像由服务端管理，各账号仅能访问自己的计划、训练与心得。
- 网页概览通过14类小组件展示真实训练数据，默认放阶段目标、热力图、计划容量、关注动作容量和月历；用户可编辑布局，按账号保存。

## 组别与历史记录

普通组和递减组按整组勾选。递减组每段记录独立的重量和次数，完成后累计各段容量、计一个完成组。组行依次显示组号、负重、次数、勾选及更多操作；计时动作显示秒数。更多菜单可转换为递减组或复制整组。复制保留全部段并置为未完成。历史详情底部可删除该次记录，确认后返回原日期；刚结束训练的总结仍可返回训练首页。

训练中点重量、次数或秒数直接在该框录入。重量允许小数，次数与秒数为整数。单侧动作分别编辑左、右值。切换字段与勾选可连续操作，只有组菜单和历史删除确认使用弹层。

训练中按当前动作查看上一次训练记录。动作名下默认显示一行摘要，点击展开可查看日期和每组的重量、次数，再次点击收起。历史数据只读，本次组表继续用于录入。

主导航为悬浮胶囊。训练、日历、动作库分别使用哑铃、日历页、四格图标，选中入口为 #242424 底、白色图标与文字。浏览动作库时三项导航选中动作库，半透明胶囊浮在列表内容上方；进行中的训练使用底部居中的浅色胶囊，最小化、加动作、写心得均为即时操作，使用深色图标与文字。计划双列的浅色实底采用 #F2F2F7。

手机主屏幕图标沿用 Figma EX 首页的 GYM 标志，保留白底、黑色图形、紫色中柱和底部 GYM 字样。桌面入口独立于 ToDo，启动后进入健身手机页。

计划预览的动作数和组数紧跟计划名，摘要锚定弹层顶部，所有动作数量采用同一标题间距。

首页「新建计划」按钮用阿里妈妈数黑体 Bold，字号 17 px，字距 0%。主稿与保存后、最小化等首页状态遵循同一样式。

## 动作库的部位与肌群

每个力量动作通常指定一个主练部位和一个主练肌群。对每个涉及的肌群标为「主练」「明显参与」或「顺带参与」。主练和明显参与均进入相应肌群小类及所属部位大类；顺带参与只在动作详情中说明。每个筛选结果按动作编号去重，跨分类共用星标与训练记录。三档表示训练侧重，无需估算百分比。

| 部位 | 肌群或训练侧重 |
|---|---|
| 背部 | 背阔肌、大圆肌、菱形肌、斜方肌上束／中束／下束、竖脊肌 |
| 肩部 | 三角肌前束／中束／后束、肩袖（冈上肌、冈下肌、小圆肌、肩胛下肌） |
| 臀腿 | 臀大肌、臀中肌、大腿前侧（股四头肌）、大腿后侧（腘绳肌）、大腿内侧（内收肌群）、小腿后侧（比目鱼肌、腓肠肌） |
| 手臂 | 二头、三头、肱肌、肱桡肌、前臂屈肌群、前臂伸肌群 |
| 腰腹／核心 | 腹直肌、腹斜肌、腹横肌、竖脊肌、前锯肌 |
| 胸部 | 上胸、胸中部、下胸 |

竖脊肌是背部与腰腹／核心共用的标签。有氧为独立分类，仅在「全部」和「有氧」列表展示。有氧卡片省略肌群三档及其编辑入口。

## 手机端原型页首与日历

整屏稿省去模拟系统时间、信号与电池，以 01 首页顶部 GYM 标志的可见边距（约 27 px）校准页首。日历年份在月份行右侧；训练日记与统计共用顶部居中双段切换栏；六周按 58 px 行距排列。日期数字、选中底、训练标签及相应点击区随所在周对齐。

## 动作主数据的同步来源

用户指定本机「已选动作肌群分类.html」为动作主数据来源。用户提出同步时，以四位动作编号关联名称、分类、器械、媒体和肌群档位，读取基础记录并叠加用户实际编辑页面所在浏览器保存的逐动作修改（folio-muscle-tags-v1:编号）。跨浏览器接手时须取得该浏览器的有效记录，单读 HTML 无法确认编辑后的标签。用户选图、修改标签或讨论设计时不触发生产同步。

原型优先复用已有画板，保留表达主要流程或关键差异所需的状态。纯样式调整直接同步主稿与现有状态。

训练总结按实际组顺序展示负重与次数、左右侧数据或时长。一个点对应一组，递减段缩进到同一个组号下。每组只区分已完成（深色实点）和未完成（浅灰实点），原计划与追加组采用相同点样式。卡片仅列实际完成的组次数据；省去图例、完成比例和组类型说明。至少完成一组的动作留在动作明细；完成零组的动作才列在底部「未训练」。

「写心得」打开时绑定本次训练的当前动作记录。切换动作后，各自读取、编辑自己的心得。训练总结及日记中的同次训练详情按动作展示，有内容时在对应卡片的组次点列下显示「本次动作心得」，无内容时收起该行。

训练总结的动作卡采用等宽双列，高度随内容自适应。右侧逐组数据与递减段完整展开；心得在卡内换行，参与卡高计算。左右列各自向下排列，同列下一张紧接上一张并保留卡间距。整行的「未训练」栏目排在两列中较低的末端之后。

手机肌群训练量卡片保留标题、表层／深层切换、正背面人体图与当前统计周期的色阶。卡片在图例后收尾。

历史计划在首页默认折叠，编辑页可归档。历史导入按来源及原记录 ID 去重，保留每场与每次动作出现的独立顺序。日历日期下依次展示训练标题和当日容量。距离和层数与秒数可独立记录，有氧心率存于后台。

## 桌面小组件规范

健身桌面沿用 [ToDo 小组件尺寸和排布规则](../ToDo/设计与写作规则.md#小组件尺寸和排布规则)。常规宽度为 292.5、600、1215、1830 px，高度为 200、420、640、860 px，横间距 15 px，纵间距 20 px。用户选定的概览组件采用 ToDo 的白底、黑白灰视觉与卡片样式，正文和控件按内容在规定尺寸内重排。

2026-11-16 用户确认，Figma EX「foilo-健身页面」内[网页端所有小组件](https://www.figma.com/design/qdopzPVPXyrlbQuaPA6ZYa/?node-id=56-9293)（Page 56:9293）是所有网页小组件的最终样式基准。开发与后续样式调整前，读取此页中对应组件的最新尺寸、字体、颜色、内边距、内容排布和控件状态，并据此实现和验收。用户后续在该页的修改优先于旧预览和历史稿。

2026-11-17 用户明确，本轮只修改网页代码，不修改 Figma。组件目录、字体与控件均只读核对，不因版本号或样式修正改动其图层。每种组件使用自己的内部排布，不用一套通用内间距近似。常规600px组件在可容纳时保持原尺寸，依1830、1215、600px减少列数；小于600px才整体等比缩放。1215px阶段卡在单列按列宽等比缩放。整页排布可随账号布局不同，组件本身的字体、间距、图表、图片和比例以目录为准。

「手机端」Page（0:1）里的网页「01 · 数据概览」（56:9370）用于整页排布与组合示意。其中的小组件副本仅用于摆放示例；与组件目录出现差异时，以「网页端所有小组件」页为准。实现时应分别读取整页结构和组件目录样式。

2026-11-16 用户要求所有网页组件具有轻微悬浮感，并通过字体设计加强层次。整卡双层投影：Figma 第一层 offset (0,6)、radius 18、spread -3、RGBA (0.09,0.105,0.13,0.09)；第二层 offset (0,1)、radius 3、spread 0、同色 alpha 0.055。统一绑定本地效果样式「Folio / 小组件 / 柔和悬浮」。2026-11-17 网页按当前工具的radius×0.85映射，CSS模糊分别15.3与2.55px，保留偏移与spread。内部元素使用更轻层次，不套整卡阴影；保留白底、14px圆角和0.5px内描边。

现行字体层次以2026-11-17最新目录为准：常规组件标题为苹方半粗20/24，月历标题为苹方半粗16px、自动行高、顶对齐；日期翻页使用苹方13px。数黑体Bold用于17px计划/分组名、24px重点动作名及动作选择弹窗标题；页签仍为数黑体19px。Bahnschrift Regular用于数值，目标完成数48/56、汇总34/42、计划容量26/30，阶段月分项28/30；图表与日历数字保留各自10—15px层级。中文正文为微软雅黑，辅助文字一般12/18。单位和分母单独降级，不与主数字套同一字级。

数黑体使用[完整原文件与发布说明](../../../public/folio/gym-titles/README.md)，不能把原292字子集继续当成完整字库。字体检查既查加载，也查浏览器逐字实际渲染字体；苹方、Bahnschrift、微软雅黑仍使用系统字体，不打包系统字体文件。当前Windows设备已实际核验，其他设备按可用字体回退，不能宣称所有平台的字形抗锯齿逐像素一致。

用户追加的月份、周等标题片段也属于完整标题，包含「11月」「本周」，必须与后面的「训练目标」「各计划目标」统一字体、字号与行高，不能因分成独立文本层而漏改。

2026-11-16 后续反馈明确：组件内保持中性黑白灰，拒绝米黄色、偏暖或偏绿的底块，拒绝在各折线图、人体图和汇总数字外围增加凹陷底台；最近训练动作卡保持纯白，不使用渐变卡底。内部层次依靠留白、细线与轻投影。细目标进度条可保留轨道和完成条的轻微明暗，柱形可保留中性灰明暗，颜色不改变数据的高度、长度及数量含义。最近训练内卡按最新主稿为255px宽、12px圆角、0.7px #E5E5E5边线及更轻投影，左右区分图片/动作/完成圆点与编号组次，递减段缩进，心得参与卡高，不裁掉真实内容。两列独立向下排，未训练放在较低列之后；内容超出外卡时内部滚动。真实动作图片保留原色。

选择动作采用弹窗：左侧为动作库入口和用户的计划，选择动作库时右侧浏览全部动作并提供搜索及部位筛选；选择计划时右侧按该计划顺序列动作。动作显示对应原图、名称和必要分类，选中项同时有边线与勾选，底部有当前动作、取消与确认。Figma保留动作库与上肢 A 两个示例状态；1.11.11已实现任意搜索、部位筛选、按计划顺序选择动作和保存。首版按动作库来源统计全部计划、按计划来源统计所选计划，并在弹窗明示范围。无历史动作应显示暂无记录，后续图表不能伪造为零容量记录。

## 训练详情三栏

左栏展示全部计划和新建入口，中栏按所选计划展示一列动作，动作左侧必须带动作库中对应的图片。右栏展示该动作在当前计划范围的个人训练数据，包括容量趋势、训练日期、逐组记录与动作心得。新建计划时，右栏切换带原图的动作库，中栏展示所选动作。用户要求仅保留正常查看与新建计划两张状态稿。日期区分有完成组、当次计划中该动作零完成组及无本计划记录。
