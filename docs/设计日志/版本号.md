# 在侧 Folio · 版本号

> 阅读顺序：先读[协作总则](00-总则.md)，再按任务阅读本文件。

登录页和各业务板块独立发布产品版本，共用以下编号规则。新板块首次确定版本时，再加入登记表。

## 编号规则

| 位置 | 含义 | 写法 |
|---|---|---|
| 第一段 | 主版本 | 从 `1` 开始，只有产品负责人决定升级时才改为 `2`、`3` 等。 |
| 第二段 | 发布月份 | 固定两位，1 月写 `01`，11 月写 `11`。 |
| 第三段 | 该板块在当年该月的第几版 | 月内第一次发布从 `1` 起，随后依次为 `2`、`3` 等。 |

例如，ToDo 在 11 月再次发布产品版本时用 `1.11.2`，登录页仍可保持 `1.11.1`。如果 ToDo 的下一次产品发布在 12 月，则该月第一版为 `1.12.1`。跨年查历史时结合发布日期识别。只有发布新产品版本时才更新展示的数字。

## 更新流程

1. 确认本次涉及哪些板块，为每个发布新版本的板块分别计数。仅重新部署同一产品版本时保留原编号。
2. 同步修改本表、Figma EX 中对应的版本文字和[网页版本值](../../lib/product-versions.ts)。上线后核对实际显示，在受影响板块的《新窗口交接》（当前状态）更新产品版本、日期和服务器发布编号，并在《设计日志》追加发布及验证记录。
3. 服务器发布编号沿用现有脚本的日期和流水号（如 `20261110-02`），供定位发布包、备份和回滚。一个发布包可以包含多个板块，各自显示自己的产品版本。
