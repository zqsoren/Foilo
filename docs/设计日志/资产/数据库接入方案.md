# 资产数据库接入方案与字段

更新：2026-11-17。用户已确认账户→明细→历史、手动余额、自动汇率和人民币汇总，以下是本轮实际实现。11月17日第04条日志中的建议稿被本说明替代；评估历史仍保留。源码已实现并本地验证，尚未迁移生产库。

## 接入方式与隔离

使用现有 [SQLite连接](../../../lib/db/index.ts)，路径为MY_LIFE_DB_PATH，默认data/life-workbench.sqlite。沿用WAL、外键和迁移事务。增加 [迁移15](../../../lib/wealth/migration.ts)，由 [migrations.ts](../../../lib/db/migrations.ts)统一登记。

| 数据 | 所在位置 | 隔离方式 |
|---|---|---|
| 身份与登录 | users、auth_sessions | 共用现有登录，不再建资产密码表 |
| ToDo | todo_workspaces、todo_activity、todo_dashboard_layouts | 保持既有用户JSON、活动与布局；资产不会写入这些表 |
| 健身 | gym_plans、gym_workouts及子表 | 保持既有关系模型；资产不会写入训练数据 |
| 资产私人数据 | assets_accounts、assets_positions、assets_valuations、assets_requests | user_id按当前服务端会话限定；父子关系使用(id,user_id)复合外键 |
| 公共资料 | 代码中的账户类型／币种，assets_fx_cache | 不含私人余额，所有用户共用通用类型和汇率缓存 |

这是同一个物理数据库内的逻辑分表与应用层用户隔离，不是不同数据库账号的权限域。备份和底层文件仍共用。不能只看Drizzle schema.ts判断全部结构，本模块和健身一样主要使用参数化better-sqlite3 SQL。

服务端操作先requireActionUser()取得身份，客户端没有提交user_id的接口。读取、添加明细和更新余额都按user_id限定；复合外键进一步拒绝跨用户挂接。ToDo widget／MCP令牌没有接入资产操作。

## 已落地表结构

| 表 | 字段 | 说明 |
|---|---|---|
| assets_accounts | id、user_id、type_code、institution、name、note、card_last4、bookkeeping_enabled、revision、created_at、updated_at | 一个实际钱包／银行卡／投资账户；id为自增内部ID，银行名为可输入文本，尾号TEXT保留0012 |
| assets_positions | id、user_id、account_id、name、category_code、side、currency_code、include_in_totals、revision、created_at、updated_at | 账户中的一笔可计价明细；币种与汇总开关在明细层；side为asset或liability |
| assets_valuations | id、user_id、position_id、as_of_date、amount_minor、note、recorded_at | 每次手动余额／当前估值，追加不覆盖；amount_minor为非负INTEGER；同日按id后录优先 |
| assets_requests | user_id、request_id、command_hash、result_json、created_at | 用户范围内幂等请求；同号同内容返回原结果，同号不同内容拒绝 |
| assets_fx_cache | cache_key、payload、fetched_at、attempted_at、failed | 公共日汇率缓存；key为latest或历史日期；payload含实际汇率日和EUR基准各币种汇率 |

本轮没有实现旧建议中的archived_at、supersedes_id、voided_at、独立布局偏好或类型字典表；不能照旧建议假定这些字段已存在。账户类型、六类入口、银行提示列表、币种精度和统计类别由 [catalog.ts](../../../lib/wealth/catalog.ts)定义。51种类型用稳定ASCII code，Figma节点ID不参与业务身份。

## 表单如何映射

| 用户输入／行为 | 存储及读取 |
|---|---|
| 选择图标类型 | account.type_code；图标由静态目录映射，不把银行／平台做成数据库列 |
| 账户名称、备注、银行、尾号 | account.name／note／institution／card_last4；银行卡必填银行及4位尾号，只收尾号 |
| 新账户余额、币种、类别、计入汇总 | 首次自动创建“账户余额”position，再写第一条valuation；一个事务完成 |
| 已有账户→添加明细 | 新position及首条valuation；名称可填美元储蓄、定期、基金等，账户可容纳不同币种／类别 |
| 更新这笔 | 新增valuation，更新position及account的revision；之前历史保留 |
| 记账时可被选择 | account.bookkeeping_enabled；只存偏好，未接通收支模块 |
| 原币金额 | valuation.amount_minor及position.currency_code；按币种精度恢复显示 |
| 账户合计／总资产／净额 | 从最新明细动态计算，不再给账户存一个重复参与统计的总余额 |

首次账户保存可通过资产类别下拉调整统计分类，新增明细可单独选择。信用／应付类型只能产生负债明细；其余类型产生资产。六类入口分组不等同于财务统计类别，资产构成按现金与存款、基金、股票、贵金属等互斥类别汇总。

## 金额和历史口径

- 输入接受最多12位整数，CNY等最多2位小数，JPY／KRW仅整数；不接受负数、指数记法或超精度值。负债录正数，净额在汇总时做减法。
- 存储是最小单位整数。汇总和换汇使用BigInt有理数运算，人民币分四舍五入；客户端传输总额为整数字符串。只有图表绘图坐标使用近似Number，不回写金额。
- 每笔截至某日取as_of_date不晚于该日的最后余额，同日取最后id。补录旧日不覆盖更晚日期的当前余额；同日更正仍保留旧条目。日期下限1999-01-04，上限当前中国标准时间日期。
- 同账户多笔只各加一次；include_in_totals关闭的仍展示在财富总览，排除于看板；账户内小计显示筛选后的明细净额。不同币种原始金额不直接相加。
- 六个月趋势以月末和今日为节点，沿用截至节点已记录的余额，没有记录的早期月份留空。历史缺汇率留空；不是交易收益或收益率。

## 自动汇率

采用 [Frankfurter v2官方文档](https://frankfurter.dev/) 的ECB provider接口：`https://api.frankfurter.dev/v2/providers/ecb/rates`，EUR为共同基准，查询12个已支持法币。比如USD折人民币为原币×(EUR→CNY)/(EUR→USD)，避免先舍入倒数。不是实时行情，不保证等于银行实际成交价。

- 最新汇率缓存1小时；历史按目标日期独立缓存，保存供应方实际公布日期。周末等可能使用更早已发布日，界面保留日期；历史不能回退到今天汇率。
- 出站请求5秒超时，同一进程同一数据库／日期并发请求复用；失败5分钟后自动重试。旧缓存可继续折算但明确提示；没缓存时显示待折算，汇总标注只含已折算部分。
- 汇率网络请求只带基准币种、目标币种和日期，不带用户ID、账户名称、余额。先提交余额事务再读取汇率，网络故障不使已保存余额丢失。
- 首版支持CNY、USD、JPY、EUR、GBP、HKD、AUD、CAD、CHF、SGD、NZD、KRW；数字货币账户也手工录入上述法币估值，不自动拉取币价。
- Windows预览通过既有代理验证，Node24可使用NODE_USE_ENV_PROXY=1；不能照搬本机代理地址。生产需要验证到api.frankfurter.dev的HTTPS出站能力，不需要API密钥。

## 页面与维护入口

入口/wealth，桌面/wealth/dashboard；两个主视图overview默认、?view=wealth，录入?view=entry。[服务端操作](../../../app/wealth/dashboard/actions.ts)负责会话；[store.ts](../../../lib/wealth/store.ts)负责校验、隔离与事务；[read.ts](../../../lib/wealth/read.ts)负责当前与历史汇总；[money.ts](../../../lib/wealth/money.ts)负责精确金额；[fx.ts](../../../lib/wealth/fx.ts)负责自动汇率。

上线使用项目既有迁移入口，启动时应用缺少的migration 15。发布前先备份数据库并按总则更新版本表；不要将本机测试SQLite或账户复制至生产。首版未实现删除、作废、编辑账户资料、交易流水、银行连接、收益计算、真实投资数量／单价核算。未来增加这些行为需要新的迁移和交互，不覆盖本次余额历史。

测试见[wealth.test.ts](../../../tests/wealth.test.ts)：12项资产测试，覆盖全部现有迁移、用户隔离、原子性、幂等、版本冲突、多币种和精度、历史、汇率缓存及缺失。全仓18文件127项通过；真实浏览器验证保存与刷新、第二账号隔离和自动汇率，尚未生产验证。
