## 2026-11-16-01｜金融资产模块启动与网页结构草案

- **范围与目标**：用户确认金融资产范围、网页优先及先讨论整体结构。包含数据看板、录入管理、银行与尾号、投资分类和多币种。
- **结果与决定**：按模板建立三份模块记录并登记索引。仅用户明确表达的要求写入规则；两个主页面、账户／类别／币种分离、分类清单与余额快照方式为待评审建议，存于当前状态。尚未修改 Figma 或应用代码。
- **设计原因**：机构、资产类型、币种分别描述存放位置、持有什么和计价方式，分开后能表达同一银行的多张卡及每张卡的多币种持有，避免银行存款与投资明细重复汇总。保留历史估值；仅凭余额变化不能计算真实投资收益。
- **资料核对（2026-11-16）**：[Investor.gov 投资类别](https://www.investor.gov/introduction-investing/investing-basics/save-and-invest/learn-about-investment-options)列举股票、债券、基金、ETF 及其他类别；[中国证券投资基金业协会：基金与银行储蓄的区别](https://investor.amac.org.cn/investread/tzbdjczs/202006/t20200603_9656.html)支持区分银行销售渠道与持有产品；[Investor.gov 资产与负债](https://www.investor.gov/introduction-investing/investing-basics/save-and-invest/figure-out-your-finances)说明资产减负债的净值口径。页面结构和默认分类属于本项目设计建议，不是资料原文，也不是投资购买建议。
- **涉及入口**：本目录三份记录、[模块索引](../在侧Folio-新窗口交接.md)。分支 main；健身窗口同期独立工作，未把其文件纳入本轮提交。
- **验证**：检查文档链接与差异；未进行界面、业务代码测试或生产发布。本轮记录提交并推送，具体结果以 Git 与回复为准。
- **遗留与接手**：先确认余额快照是否符合使用方式，再定页面职责及完整分类。资产与「消费／收支」是否关联尚未决定。
