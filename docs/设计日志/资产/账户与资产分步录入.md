# 账户与资产分步录入 · Figma设计说明

2026-11-17，按用户追加要求先修改Figma，尚未实现或发布。线上保持1.11.1／20261117-10／迁移15。设计名称提案采用「添加一笔资产」，用户后续可调整。

## 两步流程

1. **新建账户**：选类型，填账户身份与备注，点击保存账户。储蓄卡、信用卡只有银行、尾号和备注，名称自动生成，但此时不展示名称预览。理财平台为名称和备注。账户创建与余额录入不再绑定。
2. **添加账户内的资产**：保存后不离开当前页面，上方保留账户摘要，下方展开资产1。可再添加资产2，按笔编辑名称、金额、币种、类别、日期和两个开关；点击保存资产，成功后显示已保存列表，可继续添加或完成返回。

顶部采用用户截图中的单行「新建账户 › 添加资产」，当前步骤深色，其他步骤浅灰；移除重复标题、数字步骤和冗余说明。后续成功、失败等细节以组件及文字说明定义，不再逐一绘制整页原型。

示例：工商银行·尾号1234，下设活钱10,000元、一年定期30,000元，账户合计40,000元。没有额外的整卡总余额参与计算。理财平台示例为活钱10,000元和沪深300指数基金当前估值5,000元；数据均为设计示例。

## 已确认的名称与默认值

| 情况 | 账户名称处理 |
|---|---|
| 储蓄卡、信用卡 | 隐藏名称输入，银行＋尾号生成名称，数据库仍存name |
| 养老金、医保卡、公积金、现金钱包 | 预填对应名称，可直接编辑 |
| 理财平台及其他账户 | 用户填写名称；不使用平台名字自动冒充用户输入 |

每笔资产的币种默认人民币，可单独修改。类别仍使用用户认可的现有类别。记账可选从账户层下移到资产层；现金与存款默认开，其余默认关。定期属于现金与存款，因此同样默认开；稿中的定期关闭示例是手动调整，不是另加隐含分类规则。计入总资产与记账可选相互独立。

信用卡账户信息复用储蓄卡结构，主组件5:2076与既有信用页3:121已更新，不增加重复整页。后续欠款按负债口径、记账可选默认关；本轮不额外画信用卡完整第二步原型。

用户随后要求继续精简：开关说明、金额口径提醒、自动名称与默认名称提示、保存状态、待保存数量及逐笔提示都不在正常表单中显示，名称预览整块移除。账户名称统一银行＋尾号，备注独立显示。添加资产卡片收紧为960px高，垃圾桶按钮组件18:9492，各表单分别引用两次；保留字段、内容、操作和必要错误校验。

## 本轮补足的交互细则（设计提案）

- 空账户允许保存，标“待添加资产”；不伪造一笔零余额。用户主动输入0与未填写区分。
- 银行与4位尾号、平台账户名称必填；资产名称、金额、币种、类别、日期必填。金额沿用现有精度与历史日期校验。
- “添加一笔资产”展开新项，已有项收起为摘要；内部区分已保存与草稿，但页面不显示待保存文字或数量。保存资产仅提交待保存项，原子保存并用请求号去重；任意一笔校验失败保留全部填写内容。
- 每笔资产无论收起或展开，右侧均显示垃圾桶。未保存项从草稿移除；已保存资产删除及其历史处理需在实现阶段明确并验证，不能仅凭图标就硬删历史。金额变化仍通过更新余额追加历史。
- 改类别时，尚未手动调整过的记账开关跟随类别默认；用户手动选择过则保留，避免悄悄覆盖。
- 同用户银行＋尾号重复时提示已有账户，可进入该账户；同尾号确为不同卡时允许继续。尾号不能当唯一身份，也不要求完整卡号来解决。
- 保存后的“修改账户信息”应更新原账户身份，不新建账户、不改已有资产。此入口的完整编辑原型和真实保存尚未实现。
- 切换类型或离开有未保存内容时提示继续填写／放弃；保存失败留在原处，账户已成功保存的事实不回退。
- 同一投资在多个App都能看到时只录一份；基金转出、银行卡扣款等仍需手动更新两边余额。本轮没有自动交易或账户连接。
- 股票／基金等通用入口暂保留在理财分类下“其他记录方式”，与平台分开展示，不擅自删除；平台身份和每笔资产类别仍分开。
