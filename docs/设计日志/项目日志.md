## 2026-11-11-01｜建立多模块、跨窗口与跨设备记录制度

- **起因**：项目有网页、手机等不同端，多个 AI 窗口与两台电脑需要持续接手；现有交接把现状和历史混在一起，缺少独立过程记录。
- **决定**：每模块使用「当前状态、设计日志、现行规则」三份文件。保留 `新窗口交接.md` 名称作为当前状态，减少旧链接迁移。当前状态持续更新，设计日志追加过程，规则正文保存最新确认决定。
- **模块与模板**：为 ToDo、健身、宣传页补齐日志与分端状态。历史按原记录补录，没有恢复未知聊天或臆造旧决定；消费／收支、饮食、账号主页留在规划表，启动时再建档。新增三份可复制模板。
- **AI 入口**：根目录新增 `AGENTS.md`，明确接手、工作中更新与阶段结束维护；README 指向总入口。AI 负责写本轮记录，用户负责产品决定和事实纠正。
- **跨设备方案**：建议源码、文档与必要素材共用一个 GitHub 私有仓库。同模块优先接力；并行时按任务分支隔离文件，Figma 画板另行划分。GitHub 不同步聊天记忆或本机工具连接。
- **首次同步状态**：本次检查本地 `main` 尚无提交和远端。本轮没有创建仓库、提交、推送或部署。首次接入需要确定账号、仓库位置及可见性，并检查实际待上传内容。
- **收录范围**：补充 `.gitignore`，排除环境凭据、数据库及旁文件、备份、聊天恢复目录、Mac 生成包、服务器发布包和浏览器临时记录。保留源码、模块文档及现有设计素材，不删除本地文件。
- **验证结果**：本轮检查 18 份 Markdown 的 107 个本地链接及锚点，均通过；原 ToDo 五次发布流水完整保留，三模块原设计节点、发布编号与网址均可追溯。Git 收录检查覆盖 11 项应排除路径、10 项应保留路径，均符合预期；未忽略候选中无超过 50 MiB 的文件，暂存区为空。未重新检查 Figma、运行应用测试或验收线上业务；也尚未完成首次上传前的逐文件隐私核查。
- **下一步**：按新制度继续各模块；用户要求执行 GitHub 首次同步时，再配置具体仓库与第二台电脑的访问方式。

- **用户反馈**：需要了解各文件的用途，并担心第二台电脑只读取设计日志时，漏掉根目录的 AI 记录维护要求。

- **维护范围**：阶段结束时更新模块当前状态、追加模块日志；确认规则、共用变化或发布发生时，再更新相应规则、项目日志、总入口或版本表，无需每轮修改全部文件。
- **边界**：只取得文档也可理解并维护记录；源码、素材、设计源文件是否可访问仍须核对。规则是 AI 需要读到的文字约定，不会后台执行，也不自动同步设备。
- **验证**：检查文档相对链接和锚点，确认设计日志内的接手流程不再依赖根目录文件；业务功能、Figma 与部署均未改动。
